# Docs and releases

- **DR1:** The documentation site is `docs/`, published by GitHub Pages from `main` at https://psyb0t.github.io/go-workflows/ with the Just the Docs theme (`remote_theme` pinned in `docs/_config.yml`, colors in `docs/_sass/`, the shared visitor tracker in `docs/_includes/head_custom.html`). `docs/source/` is excluded from the site. The site title equals the README H1.
- **DR2:** Every page has front matter with `title`, a 50 to 170 character `description` and `nav_order`. Links from `docs/` to files outside it use full `https://github.com/psyb0t/go-workflows/blob/main/<path>` URLs (`tree/` for directories). README links to the site use full `https://psyb0t.github.io/go-workflows/...` URLs.
- **DR3:** After a docs change, run `make docs` and check the built site in `.testing/docs-site`. A public API or behavior change updates the matching docs page in the same change.
- **DR4:** `CHANGELOG.md` entries are `## vX.Y.Z`, then bullets starting with a verb ("Fix", "Add", "Log", "Keep"), then a closing line saying whether migration is needed.
- **DR5:** A release is an annotated `vX.Y.Z` tag on a commit whose `main` pipeline run passed. The tag message's first line is exactly `vX.Y.Z`, then a blank line, then that version's CHANGELOG section. Set the same version in `.agents/.codex-plugin/plugin.json` before tagging. `make check-release-tag` validates the tag in CI, and the full procedure is in `docs/releases.md`.
